# 广州 18-25K「AI 产品经理」岗拆解

先说总的判断：**这不是一个"要你造大模型"的技术岗，而是一个"要你把公司已有的 AI 能力变成能卖给客户、能交付、能复购的产品/服务"的商业化落地岗。** JD 里那一串 Prompt / RAG / 向量库 / 微调 / Agent 是"门槛话术"，真正决定录不录用的是最后那句"优先 ToB 落地经验"。

---

## 1. 这个岗位真正在招什么样的人？团队现在卡在哪？

**翻译成人话：招一个"能把 AI 能力翻译成客户愿意买单的交付物"的人，而不是再招一个会调模型的工程师。**

为什么：JD 把大模型技术栈从头列到尾，但优先项却指向"知识库 / Copilot / 智能助手 / ToB 解决方案"——这是典型的信号：**模型他们不缺（自研系统已经有了），缺的是"从能用 → 能卖 → 能交付"这后半段的人。**

**团队具体卡在这三个位置（按主次）：**

- **卡在「技术自嗨，没有商品化」。** 系统能跑 Demo，但没有人把它定义成客户能签单、能验收、能复购的产品形态。
  为什么：这是一家营销**服务商**，不是技术公司；自研系统如果只对内提效、不对外卖，就是成本中心，老板必须让它变现。

- **卡在「技术负责人兼着对接客户，已经撑不住」。** 模型团队和客户/销售之间缺一个中间层做需求翻译和预期管理。
  为什么：ToB AI 交付最难的不是技术，是把客户模糊需求翻译成可实现需求、再把模型不确定性翻译成客户能接受的预期——工程师干不了也不愿干这活。

- **卡在「AI 内容能力是横的，客户需求是竖的」。** 一套通用内容系统，要落成小红书生态里不同行业的垂直解决方案。
  为什么：服务商的生意是"按客户场景定制 + 复用"，没有懂行业又懂模型边界的人做"通用能力 → 垂直方案"的封装，交付成本会失控。

## 2. 18-25K（广州）能招到的四类候选人画像

先说结论：**这个价位能稳定招到的主力是 A 类和 B 类，C 类靠"捡漏"，D 类是隐藏最优解。**

**A 类｜业务转型派（最主流）**：2-4 年内容/运营/传统产品背景，近 1-2 年自学 + 做过 1 个内部 AI 落地项目。
- 强项：懂内容/营销场景，落地执行强，性价比高，能扛脏活。
- 短板：AI 深度靠"刷课 + GPT"，Prompt/RAG 只到"会用"不会"设计"，扛不住技术负责人深挖，一追问就露馅。
- 为什么：这是 18-25K 能筛到的最大人群，但也是"做过"和"懂"分野最明显的一类。

**B 类｜技术转型派**：2-4 年算法/后端/数据出身转 PM。
- 强项：真懂 Prompt / RAG / 微调 / 向量库，能和工程师平等对话，有评估模型产出的方法。
- 短板：产品 sense 和 ToB 客户把握弱，容易过度技术化，讲不到业务价值，商业化、PRD 是短板。
- 为什么：他们能通过技术面，但最容易栽在"老板只关心这东西能不能卖钱"这一关。

**C 类｜正统大厂/明星 AI 公司 AI PM（捡漏型）**：方法论完整、见过规模化 AI 产品。
- 强项：完整产品体系 + 真 ToB 解决方案经验。
- 短板：贵（通常要 25K+）、看不上乙方服务商、不熟小红书垂直生态、习惯大厂资源不愿做交付脏活。
- 为什么：这个价位只能等到"被裁/平薪跳/从一线回二线"的人，概率低但值得老板重点关注。

**D 类｜营销服务商里搞 AI 提效的内容/增长人（隐藏最优）**：
- 强项：最懂小红书生态和客户痛点，上手即用，几乎没有学习成本。
- 短板：AI 深度不够，往往是"AI 工具高手"而非"建 AI 系统的人"，缺系统架构判断力。
- 为什么：A 类最匹配薪资、D 类最匹配业务；如果 D 类补上技术短板，是最贴合岗位的复合型人选。

## 3. 为什么有自研系统还要外招 AI 产品经理？三种真实原因 + 对应考察重点

**按可能性排序：原因 1 > 原因 2 > 原因 3。**

**原因 1（最可能）：系统是技术团队的自嗨，没商品化、没法变现。**
- 面试考察重点：产品定义与商业化能力——怎么把 AI 能力包装成卖点、怎么定价、怎么定验收标准/SLA、怎么管理客户预期、有没有"谁买单、怎么验收、怎么复购"的真实案例。
- 为什么：服务商的核心命题就是变现，自研系统不赚钱就必须外招会"商品化"的人来补这块。

**原因 2：系统要"走出内部提效、对外卖方案"，原来技术负责人兼对接客户已到极限。**
- 面试考察重点：翻译与跨职能协作能力——能不能把客户模糊需求翻译成技术可实现的需求，能不能反过来把模型不确定性翻译成客户能接受的承诺，会不会做需求边界和拒单。
- 为什么：ToB AI 交付最稀缺的是"懂两头"的中间层，这个人是用来替代技术负责人被客户反复拉扯的时间的。

**原因 3：要跟 Agent / 知识库 / Copilot 新形态，定义下一代产品方向，防止被同行抢单。**
- 面试考察重点：技术判断力——RAG / 微调 / Agent 各自适用场景与选型逻辑、Prompt 可维护性、有没有评估体系（不是只会说"我用了 RAG"）。
- 为什么：这是"加分项原因"，招进来的人若能顺带指明方向最好，但不是招聘的主驱动力。

## 4. 8 个区分「做过 AI 产品」和「懂 AI 产品」的面试问题

每个问题括号里是"它在区分什么"。

1. **"你做的那个 RAG 知识库，答错/检索不准时，你怎么定位是检索问题还是生成问题？用了什么评估指标？准确率从多少提到多少？"**
   （区分：懂的人能说召回率、chunk 策略、重排、引用率、前后数字；做过的人只会背名词、报不出数。）

2. **"你的 Prompt 上线后由谁维护？怎么防止改坏？有没有回归测试？"**
   （区分：懂的人把 Prompt 当"要版本管理 + 评测的资产"；做过的人把它当"一次性咒语"。）

3. **"同一个需求，什么情况下选 RAG，什么情况下选微调，什么时候两个都不用直接上 Agent？给一个你实际做过的判断例子。"**
   （区分：懂的人给决策树，用成本/延迟/更新频率/数据量讲理由；做过的人只会背定义。）

4. **"你的 AI 产品上线后一次调用多少钱？token 成本占毛利多少？你怎么降的？"**
   （区分：懂的人有成本账本；做过 Demo 的人没算过账。）

5. **"客户问'你保证 100% 准确吗'，你怎么回答，并且怎么把答案写进合同/SLA？"**
   （区分：懂 ToB 的人讲预期管理、兜底机制、人机协同；不懂的人回避或吹牛。）

6. **"你选的哪个向量数据库？为什么？你的数据量、embedding 模型、检索延迟分别是多少？"**
   （区分：真落地过 vs 道听途说。）

7. **"Agent 编排里你遇到过工具调用失败或死循环吗？你怎么设计兜底、超时、重试？"**
   （区分：真做过 Agent 的人一定踩过坑，能讲 failover 和状态机；没做过的人答不出来。）

8. **"如果让你评估一个 AI 内容系统行不行，你会建哪几个指标？为什么不用'像不像人写的'这种主观标准？"**
   （区分：懂的人讲可量化指标——事实性、一致性、风格匹配、复用率、人工改稿率、成本下降；做过的人只讲"感觉写得不错"。）

## 5. 想比同档候选人更强，必须展示的三种能力

**能力一：用数字证明"我让 AI 从能用变可用/可卖"的交付能力。**
- 展示什么：1-2 个"闭环案例"，带**前后对比的具体数字**——准确率、人工改稿率、成本、人效，并且讲清**你个人在这个结果里的动作**（不是团队功劳）。
- 怎么展示：准备一个 30 秒能讲完的 STAR + 数字案例，配一页"指标曲线或 before/after 表"。
- 为什么：18-25K 档最不缺"做过 AI"的人，最缺"证明自己做出结果"的人，数字是唯一能把你和同龄人拉开的东西。

**能力二：对模型能力边界的判断力（能说清什么能做、什么不能做、为什么）。**
- 展示什么：一张"能力边界地图 / 选型决策表"，例如"这个场景用 RAG 是因为数据天天变、微调不划算""这个场景用规则兜底是因为模型幻觉成本太高"。
- 怎么展示：**主动抛一个"我不会用大模型硬做的场景"**，展示你懂边界——面试官最怕的就是候选人过度承诺客户、把项目做砸。
- 为什么：在乙方，懂"边界"比懂"名词"值钱得多，因为超出边界的承诺会变成交付事故和赔款。

**能力三：从技术到业务的"翻译 + 商业化"能力。**
- 展示什么：一页纸方案——假设面对一个小红书营销客户，你怎么把这套 AI 内容系统包装成可卖的产品/服务，含卖点、定价逻辑、验收标准、预期管理话术。
- 怎么展示：面试中主动说"我会这么跟客户谈"，把话题从技术拉回"怎么签单、怎么交付、怎么续费"。
- 为什么：这家公司缺的就是站在"服务商变现这一侧"的人，你越早表现出"我是来帮你赚钱的"，越早跳出工程师思维。

## 6. 这类候选人最容易犯的三个错误

**错误一：过度讲技术（把面试当技术分享）。**
- 为什么错：这是一家要卖服务给客户的营销公司，缺的是"把技术变成钱"的人，不是另一个工程师；你越往 RAG/微调原理深处讲，越暴露你站在技术侧而非商业侧。

**错误二：Demo 做得像玩具，讲不出生产环境。**
- 为什么错：这个价位要的是"落地过、踩过坑、扛过客户"的人；一个"调 API 做的聊天机器人"恰好证明你只到"会用工具"这一层，和岗位要的"落地经验"完全相反。

**错误三：把 ToC 和 ToB 经验搞混（用 C 端增长/体验思路答 B 端题）。**
- 为什么错：这家公司是 ToB 服务商，买单逻辑是"客户签单—交付—复购"，C 端的流量—体验—留存逻辑在这里失效；大谈 DAU、留存、用户体验，等于直接告诉面试官你没做过 ToB。

---

**一句话总结给候选人**：这岗位要的不是"最懂模型的人"，而是"能把模型变成客户续费理由的人"——面试全程请把每一句技术话，都收尾在"这对客户值多少钱、怎么验收、怎么复购"上。
